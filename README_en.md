# Lua Simple Class

Possibly the first Lua class library with modern syntax that doesn't interfere with—but rather enhances—static analysis tools.

Offered as a lightweight version of [Luaclass](https://github.com/blanhhy/luaclass), it simplifies runtime behavior while retaining core OOP capabilities.

## Installation

`simpleclass` is implemented entirely in Lua; simply download [this folder](simpleclass) to use it anywhere.

> **All in One** file is available!!\
> Can be easily integrated into any Lua project\
> [simpleclass.lua](variant/simpleclass.lua)

Compatible with Lua 5.1 and later, including LuaJIT.

If you use [LuaRocks](https://luarocks.org/), you can also install it with the following command:

```bash
luarocks install simpleclass
```

Or build from source into the current rocks tree (e.g., the `lua_modules/` directory generated by `luarocks init`):

```bash
luarocks make --tree=lua_modules simpleclass-1.0.2-1.rockspec
```

## Quick Start

### Import the Module

```lua
require "simpleclass"
```

By default, this performs a global import, which registers all module interfaces under `_G`. If you prefer not to do this, you can disable [global imports](#global_imports)

> Guide:
> Using a third-party importer that supports arguments is a good option, but you can also do this directly:
> ```lua
> local sc = require "simpleclass.with" {GLOBAL_IMPORT = false}
> ```

### Defining Your First Class

```lua
class "MyClass" {
    foo = function(self)
        print("foo from", self:getClass())
    end;
}

local obj = MyClass()
obj:foo() --> "foo from    MyClass"
```

For more sample code, see [Demo](demo/)


## Features

### Classes

Defining a named class:

The syntax is `class "<name>" {<body>}`

> Once created, a named class is located in the `simpleclass._ENV` environment; a class with the same name will override the previous definition. If [automatic global classes](#automatic-global-classes) are enabled, global variables will also be registered for the class

Class Members:

Static fields, instance fields, instance attributes, instance methods, class methods, static methods, constructors, and metamethods

> In Lua, instance methods are called using `:`; by convention, the first argument of the function is named `self`. Class methods follow a similar logic.
>
> `SimpleClass` uses `__init` as the constructor name and is also compatible with `constructor` as an alias during definition.
>
> Fields defined directly within the class body become static fields, shared by all objects; metamethods are native to Lua, and since a class is the metatable of its instances, you can define metamethods to alter the behavior of instances.

Instantiation:

You can use either `clazz:new()` or `clazz()`
If you are using LuaLS, the former is the recommended syntax

> Example: Named Class
>
> ```lua
> class "NamedCls" {
>     __init = function(self, arg1, arg2)
>         self.arg1 = arg1
>         self.arg2 = arg2
>     end;
>     print = function(self)
>         print(self.arg1, self.arg2)
>     end;
> }
>
> local obj = NamedCls:new("hello", "world")
> obj:print() --> "hello world"
> ```

Getter & Setter Properties:

Use `property` to define properties; properties can have getter and setter methods

- Getter: The function name is `get.<attr>`, which makes `obj.attr` readable
- Setter: The function name is `set.<attr>`, which makes `obj.attr` writable

> Example: Defining Getter & Setter
>
> ```lua
> class "Counter" {
>     __init = function(self, init)
>         self._count = init or 0
>     end;
>     property.count;
>     ['get.count'] = function(self)
>         return self._count
>     end;
>     ['set.count'] = function(self, new)
>         self._count = new
>     end;
> }
>
> local obj = Counter(10)
> print(obj.count) --> 10
> obj.count = 20
> print(obj.count) --> 20
> ```
> Note: It is not necessary to implement both; you can have read-only, write-only, or even none at all.

Anonymous classes: Temporary classes that do not require a name and are not registered in the environment.

> Example: Anonymous class
>
> ```lua
> local cls = class {
>     foo = function(self)
>         print("foo from anonymous class")
>     end;
> }
>
> local obj = cls()
> obj:foo() --> "foo from anonymous class"
> ```
>
> Note:
> When defining a named class, if you pass an empty argument, an empty string, or a non-string argument, it will always be interpreted as an anonymous class.
> For example, `class() {}` can also create an anonymous class, and you can even use `extends` and `implements`.

### Class Inheritance

- Single Inheritance: simpleclass supports only single inheritance.

  Classic Syntax: Use the `extends` keyword + a class name string  
  Shorthand Syntax: Write the base class name directly, e.g., `class "Cls" : Base {}`

> In shorthand syntax, the base class must immediately follow the class body; if other keywords (such as `implements`) are used, they must precede it.

- `super`: Calls a parent class method as a subclass object.

  Takes the current class and `self` as arguments; example: `super(this_cls, self):foo()`
  > `self` can be either an instance object or a class object

  When calling the parent class constructor, the name can be omitted; example: `super(cls, self)()`
  If the `debug` library is available, `super()` can be called without passing arguments, similar to Python

> Example: Single inheritance
>
> ```lua
> class "MySubCls" : extends "MyClass" {
>     ---@Override
>     foo = function(self)
>         super(MySubCls, self):foo() -- call parent's foo
>         print("improved foo")
>     end;
> }
>
> local obj = MySubCls:new()
> obj:foo() --> foo from MySubCls
>           --| improved foo
> ```

### Interfaces

An interface is a set of method signatures that defines the methods a class must implement.

An interface is not a class and cannot be instantiated.

Interfaces can be implemented by classes, and it is possible to check whether a class has implemented a method. Additionally, there is a relationship similar to inheritance between interfaces, but this does not form an inheritance chain.

- Interface definition: Use `interface`; the syntax is similar to that of a class definition.
- Anonymous interface: Similar to an anonymous class.

> Named interfaces are also located in `simpleclass._ENV` and follow the exact same rules as named classes.

> Example: Interface definition
>
> ```lua
> interface "CanFly" {
>     "fly"; -- only method names
> }
> ```

- Interface implementation: Use the `implements` (or `impl`) keyword; a class can implement multiple interfaces

> Example: Interface implementation
>
> ```lua
> class "Bird" : implements(CanFly) {
>     fly = function(self)
>         print("bird is flying")
>     end;
> }
>
> local obj = Bird()
> obj:fly() --> "bird is flying"
> ```

### Combining Interfaces

When defining an interface, you can use the `extends` keyword to combine multiple interfaces

> Example: Combining Interfaces
>
> ```lua
> interface "CanEat" {
>     "eat";
> }
>
> interface "BirdLike" : extends(CanEat, CanFly) {
>     "spawn";
>     "nest";
> }
> ```

As shown above, you can define new methods while combining other interfaces.

### Type Checking

**`type(obj)`**

  > This is not the `type` function from the Lua standard library

Usage:

```lua
local ctype = require("simpleclass").type
print(ctype(obj), ctype(10))
```

- Returns the class of an object from the SimpleClass library
- For Lua primitive types, behaves identically to the standard library's `type` function

**`isinstance(obj, cls)`**

Usage:

```lua
isinstance(MyClass(), MyClass)
obj:isInstance(SomeClass)
```

- Checks whether an object is of a specified type
- The type can be a class, an interface, or a Lua primitive type
- Objects can directly call the `isInstance` method, which is equivalent to `isinstance`

**`issubclass(cls1, cls2)`**

Usage:

```lua
issubclass(Dog, Animal)
```

- Checks whether a class inherits from another class (including indirect inheritance)
- Note: **Calling this on the same class returns `true`**

**`isimplements(cls, ...interface)`**

Usage:

```lua
isimplements(Bird, CanFly)
```

- Checks whether a class implements a specified interface (multiple interfaces are allowed)
- Returns a boolean value and an index of the first unimplemented interface (if any)

**`isimpl(cls, i)`**

Usage:

```lua
local isimpl = require("simpleclass").isimpl
isimpl(Person, CanFly) --> false, "fly"
```

- Checks whether a class implements a specified interface (single interface only)
- Returns a boolean value and the name of the first unimplemented method (if any)

The classes and interfaces accepted or returned by the methods above are the objects themselves.

### Type Inference

SimpleClass provides a type inference plugin for [lua-language-server](https://github.com/LuaLS/lua-language-server). Below is a sample `.luarc.json` configuration:

```json
{
  "runtime.plugin": ".luals/simpleclass.plugin.lua"
}
```

Simply copy the plugin script and `simpleclass.d.lua` to your workspace.

If you installed via LuaRocks, the plugin files are located in the rock's configuration directory. First, run the following command to find the directory for the current version:

```bash
luarocks show --rock-dir simpleclass
```

Note the output path as `<rock-dir>`, then configure:

```json
{
  "runtime.plugin": "<rock-dir>/conf/simpleclass.luals/simpleclass.plugin.lua",
  "workspace.library": [
    "<rock-dir>/conf/simpleclass.luals"
  ]
}
```

> Note: `runtime.plugin` refers to the LuaLS plugin path, not the LuaRocks Lua module path; after upgrading `simpleclass`, simply run `luarocks show --rock-dir simpleclass` again to retrieve the new path.

An optional patch script is also provided to enhance the plugin's capabilities.

> Note: Patches hook into LuaLS's internal behavior and may affect normal functionality; they are also unstable across versions.

To apply patches, you must also copy the corresponding patch files and maintain the same directory structure.

```
[DIR]
├── simpleclass.plugin.lua # Core plugin
└── patches/               # Patch script directory
```

Automatic Type Declaration:

- Recognizes DSL syntax to automatically generate static type annotations, eliminating the need for manual type annotation
- `@static` becomes a valid annotation, used to declare members on classes rather than instances
- Uses dual-type semantics and custom diagnostics to simulate interface types that do not exist in LuaLS

Assisted Type Inference:

- Intelligently identifies method context; for methods known to the class, automatically binds the first parameter to the type of the class or object
- If an instance method parameter is to be assigned to a field, and the field type is declared but the parameter type is unknown, automatically annotates it with the field's type
- When `super` is used to call a method within an instance method, the plugin automatically replaces it with the parent class object, thereby providing parameter hints for the parent class's method

Static Type Checking:

- `@override` is treated as a valid annotation; it checks whether the method actually exists in the superclass and issues a warning
- When defining a class that implements an interface, LS automatically checks whether the class implements the required methods of the interface and issues an error
- [Patch] Enhanced `@overload` signature dispatch: specific types and subtypes take precedence, and union types within the scope are excluded

More features await discovery

> Warning:
> Static inference relies on the LuaSimpleClass DSL.
>
> If you are not using global imports, you must manually `local` the module interfaces used in each file to ensure function names match those in the global import.
> ```lua
> local class, super = sc.class, sc.super -- etc.
> ```

## Configuration Options

### Global Import

Automatically registers module interfaces in `_G` and enables [Automatic Global Classes](#automatic-global-classes)

Set to `false` if you do not want to pollute the global environment.

- Category: **Import** option
- Field: `options.GLOBAL_IMPORT` in [init.lua](simpleclass/init.lua)
- Default: `true`

### Include Interfaces

Enables features related to interfaces.

Set to `false` to trim interface modules.

- Category: **Import** option
- Field: `options.INTERFACE_INCLUDED` in [init.lua](simpleclass/init.lua)
- Default: `true`

### Default Interface Features

The default value for [interface features](#interface-features)

If set to `"lexical"`, this allows for the inclusion of LS features only, without the runtime.

- Category: **Import** option
- Field: `options.DEFAULT_I_FEATURE` in [init.lua](simpleclass/init.lua)
- Default: `"general"`

### Automatic Global Classes

When defining a class, checks whether the global variable name is available; if so, automatically registers it as a global variable

- Category: **Runtime** option
- Field: `simpleclass.AUTO_GLOBAL`
- Initial value: Same as [Global Import](#global-import)

### Interface Features

`general` enables all features; `nocheck` skips runtime interface checks (always returns `true`), suitable for temporarily disabling checks, and is safely interchangeable with `general`; `lexical` retains only lexical elements for LS analysis, without any runtime features; object creation skipped during this process is not backfilled, making it somewhat irreversible

If you have already used the interface and wish to deprecate it, you can simply set it to `"lexical"` to prevent existing DSLs from throwing errors

- Category: **Runtime** option
- Field: `simpleclass.I_FEATURE`
- Default: Same as [Default Interface Features](#default-interface-features)
